# LeadCRM project structure

## Workspace layout

`frontend`, `backend`, and `shared` are npm workspaces orchestrated by Turborepo. Current paths below describe implemented modules rather than historical SaaS or field-service plans.

```text
OWN-CRM-1/
├── frontend/
│   ├── app/                     Next.js App Router shells and API proxy
│   └── src/
│       ├── features/tenant/     Domain UI, hooks, API services, and local types
│       ├── shared/              Reusable components, transport, hooks, guards
│       ├── store/               AuthContext, DataContext, projections, dev mocks
│       └── lib/                 Frontend utilities
├── backend/
│   ├── prisma/                  Schema and forward SQL migrations
│   ├── scripts/                 Migration rollout and isolated test harnesses
│   └── src/
│       ├── api/                 Express routes and middleware
│       ├── core/                Auth, permissions, tenant context, audit
│       ├── modules/             Domain controllers/services/repositories
│       ├── integrations/gmail/  Scoped mailbox, OAuth, scheduling, sync
│       ├── config/              Validated application/database configuration
│       ├── database/            Development seeders and operational scripts
│       └── shared/              Backend helpers and errors
├── shared/
│   ├── src/                     Canonical types, schemas, contracts, helpers
│   └── scripts/                 Generated JavaScript synchronization
├── infrastructure/             Deployment configuration
├── docs/                       Plans, behavior definitions, verification reports
├── package.json                Workspace commands and pinned runtime metadata
└── turbo.json                  Build/lint/dev task graph
```

## Frontend route and module map

| Route | Main domain location |
| --- | --- |
| `/login`, `/change-password`, `/reset-password` | `features/tenant/auth` |
| `/dashboard` | `features/tenant/dashboard` |
| `/reporting` | `features/tenant/reporting`; reuses Dashboard |
| `/crm/leads`, `/crm/contacts`, `/crm/accounts` | `features/tenant/crm`; list/detail/import routes |
| `/crm/deals`, `/crm/pipeline` | `features/tenant/crm/deals`, `crm/pipeline` |
| `/operations/taskboard` | `features/tenant/operations/tasks` |
| `/automation/workflows` and new/edit routes | `features/tenant/automation/workflows` |
| `/marketing/campaigns`, `/marketing/forms` | `features/tenant/marketing` |
| `/inbox` | `features/tenant/inbox` |
| `/settings` and profile/account routes | `features/tenant/settings`, `administration` |
| `/notifications`, `/help` | Matching tenant features |
| `/forms/:publicId` | Public form rendering in `features/tenant/marketing` |

`/administration/users` redirects to Settings → Team Management. Other retained compatibility shells are not evidence of an additional supported module. Service-order, asset, inventory, SaaS checkout, and platform-admin modules are retired.

## Backend domain map

- `modules/crm`: Leads, Contacts v2, companies/Accounts, Deals, pipelines/stages, imports, relationships, merge, activity, Custom Fields and record files.
- `modules/operations/tasks`: Tasks, summary/options, bulk updates and assignment lifecycle.
- `modules/automation`: Workflows, triggers/actions, execution and assignment.
- `modules/marketing`: Campaigns/audiences, templates, Forms/public submissions.
- `modules/administration`: Users, Groups, roles/permissions, Products, organization settings, audit and Archived Data.
- `modules/reporting/reports`: Dashboard aggregates/export/events plus compatibility reports.
- `modules/notifications` and `modules/preferences`: Personal notifications and saved view preferences.
- `integrations/gmail`: Mailbox scope/store, OAuth, sync, recipient checks, send/drafts, scheduled mail and events.

The exact public API surface is registered in `backend/src/api/routes/index.ts` and its imported route files. Domain services use the existing transaction and tenant context helpers; preserve those boundaries when extending them.

## Shared sources and generated output

`shared/src/types`, `contracts`, `constants`, `validation`, and `utils` define common models and behavior. Both workspaces import `@leadcrm/shared`. TypeScript is canonical; compatibility `.js` companions are generated by the shared build and should not be maintained by hand. Frontend-only record projections remain under `frontend/src/store/types`.

## Current migration additions

- `backend/prisma/migrations/20261116000000_user_groups`: convert legacy Department values while preserving existing membership.
- `backend/prisma/migrations/20261117000000_campaign_submission_recovery`: durable leases, recipient attempts and interrupted outcomes.
- `backend/prisma/migrations/20261118000000_group_revisions`: refresh existing authenticated views after Group changes.
- `backend/prisma/migrations/20261119000000_notification_utc_timestamps`: preserve history and make new notification/outbox timestamps independent of the database session timezone.

Apply these after the existing migration history and before running the new backend. See [rollout](../README.md#forward-rollout).
